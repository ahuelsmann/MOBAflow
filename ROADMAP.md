# MOBAflow Roadmap

MOBAflow evolves in small, testable slices. GitHub issues are the source of truth; this page groups them by outcome rather than promising dates.

## Now — reliable locomotive management

- [Digital address conflicts](https://github.com/ahuelsmann/MOBAflow/issues/12): detector and management summary.
- [Maintenance history and reminders](https://github.com/ahuelsmann/MOBAflow/issues/13): validated schedules, counters and status.
- [Decoder profiles and CV backups](https://github.com/ahuelsmann/MOBAflow/issues/14): atomic import/export and comparison.
- [Digital locomotive passport](https://github.com/ahuelsmann/MOBAflow/issues/15): printable, privacy-safe output.
- [Locomotive whistle automation](https://github.com/ahuelsmann/MOBAflow/issues/4): feedback-triggered momentary functions.

## Next — release confidence

- Complete the [locomotive and release epic](https://github.com/ahuelsmann/MOBAflow/issues/16).
- Run the signed-tag Windows acceptance described in [Release Studio](docs/RELEASE-STUDIO.md).
- Raise coverage first in Z21 receiving, UDP lifecycle and runtime command paths.
- Add an explicit Android/MAUI smoke-build lane.

## Later — community and ecosystem

- Optional QR/deep-link integration after a stable public locator contract exists.
- Additional track libraries and hardware adapters behind neutral contracts.
- Contributor-focused examples, screenshots and hardware compatibility reports.

See the [open issues](https://github.com/ahuelsmann/MOBAflow/issues), [quality runs](https://github.com/ahuelsmann/MOBAflow/actions/workflows/quality.yml), [releases](https://github.com/ahuelsmann/MOBAflow/releases) and [changelog](CHANGELOG.md) for the current state.

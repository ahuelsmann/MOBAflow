# External mutation enforcement and reconciliation matrix

Source: [#337](https://github.com/ahuelsmann/MOBAflow/issues/337). Research date 2026-10-18. These are researched interface facts and PROPOSED qualification requirements, not proof that an account or broker currently enforces them.

## Common enforcement rule

No issue-controlled worker receives central write credentials. A proposed trusted operation boundary must reject stale epochs/grants and prevent stale controllers from obtaining new credentials. Before replacement, neutralize old execution/egress/identities and reconcile accepted/in-flight requests. Revocation of future calls is not proven rollback of an accepted request. Unknown in-flight work blocks conflicting owner/controller transfer.

Classes: Conditional = documented resource precondition; Guarded = no sufficient API owner/CAS precondition, needs qualified sole-operation/credential/quiescence boundary; Excluded = unsupported/not qualified or outside scope. All rows are DISABLED for autonomous execution until their exact route passes qualification and applicable decisions. A preflight GET or clientMutationId is not atomic fencing/idempotency. No blanket acceptance of residual risk.

## Required qualification evidence

For each enabled row retain endpoint/version, request schema, identity permissions, exact conditional field (or absence), dispatch authority, stale actor test, uncertain-response test, external readback, actual terminal end, decision/grant references and residual limitations. Test an obsolete controller as well as worker; model prompts or a database lock alone cannot prove exclusion. Include an already-in-flight request that completes after lease loss; hold transfer until known.

Fencing a reviewer is not replacing its independent route. The existing Claude plan must accept any future technical publication/callback boundary; if its credentials/routine cannot enforce required ownership, admission remains blocked. Do not add a parallel controller merge permit or second review dispatcher.

At most one serialized intent per affected resource is dispatching/unknown. Bounded internal retry applies only to transactional conflicts or proved safe reads/no-effect actions under current authority; semantic repeated mutation remains forbidden while uncertain. Denial is a result, never a reason to bypass protection.
